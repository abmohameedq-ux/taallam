- تعليمات المعلّم الذكي تمنع إكمال الإجابة بمعلومات خارج النص المحدد.
- يظل استخراج النص وOCR مشروطين بتثبيت الاعتماديات وأدوات النظام؛ لم يُدّعَ اختبار نشر فعلي.

- إضافة `GET /api/admin/pdf-status` لمالك المنصة؛ يعرض حالة `pdf-parse` وأدوات OCR واللغات المتاحة، إضافة إلى مسار تخزين البيانات. لا يكشف هذا المسار معلومات لغير مدير المنصة.

- لم يُعتبر رفع الكتب أو OCR مختبرًا فعليًا في هذا الإصدار؛ يوفّر تشخيص الجاهزية خطوة عملية للتحقق بعد النشر.


## الإصدار 2.31.0 — قراءة ملفات PDF المصوّرة ومعلومات الفصل الدراسي
- مكتبة `pdf-parse` اعتماد إلزامي؛ تثبّت عند تشغيل `npm ci` أو `npm install`. إذا غابت المكتبة، يتوقف الخادم عمدًا ولا يقدّم تجربة تعليمية ناقصة.
- عند رفع كتاب PDF، يستخرج النظام النص المضمّن. إذا كان الملف ممسوحًا ضوئيًا ولا يحتوي على طبقة نص، يحاول OCR عبر `pdftoppm` و`Tesseract` مع اللغتين `ara+eng` عند توفرهما على الخادم.
- محاولة OCR الحالية محدودة بأول 100 صفحة للكتاب المصوّر، ويجب مراجعة النص الناتج لاحتمال أخطاء التعرف، خصوصًا في الرياضيات والجداول. إذا لم تكن أدوات OCR مثبتة في بيئة الاستضافة، تظهر رسالة واضحة بدل الادعاء بنجاح القراءة.
- أضيف حقل الفصل الدراسي إلى بيانات الكتاب والبحث في المكتبة العامة.
- لا تُعتبر قراءة PDF بديلًا عن معاينة الكتاب الأصلي؛ يُحتفظ بالملف الأصلي للمعاينة والتنزيل، ويُستخدم النص المستخرج للبحث والتعلّم الموجّه إلى محتوى الكتاب.

### متطلبات التشغيل الخاصة بـ PDF وOCR
1. تثبيت اعتماديات Node.js: `npm ci` (أو `npm install`).
2. لملفات PDF النصية يكفي اعتماد `pdf-parse`.
3. للكتب المصوّرة، ثبّت على الخادم Poppler الذي يوفر `pdftoppm`، وTesseract مع بيانات اللغة العربية والإنجليزية (`ara` و`eng`). في Railway، تأكد من تضمين هذه الحزم في صورة/بيئة النشر؛ لا يثبتها `npm install` تلقائيًا.
4. اضبط `DATA_DIR` على Volume دائم لحفظ الكتب المرفوعة وبياناتها بين عمليات النشر وإعادة التشغيل.

## الإصدار 2.21.0 — متابعة أولياء الأمور وربط الأبناء بالمدارس
- إضافة واجهة مستقلة لمتابعة الأبناء عبر `/guardian`، تستخدم حساب ولي الأمر الحالي.
- يستطيع ولي الأمر طلب ربط حسابه بطالب عبر اختيار المدرسة وإدخال البريد المدرسي للطالب.
- لا تُكشف بيانات الطالب بمجرد إرسال الطلب؛ يجب على إدارة المدرسة اعتماد الربط، ويُتحقق وقت الاعتماد من وجود حساب طالب معتمد ونشط في المدرسة بالبريد المحدد.
- إضافة قسم «أولياء الأمور» في إدارة المدرسة لمراجعة طلبات الربط وقبولها أو رفضها.
- بعد الاعتماد، يرى ولي الأمر معلومات الطالب الأساسية والواجبات المنشورة الموجهة إلى صفه وشعبته وحالة التسليم والدرجة والملاحظات بعد التصحيح.
- بيانات الربط محفوظة في `guardian-links.json` داخل `DATA_DIR`، ومقيدة بمعرّف حساب ولي الأمر ومعرّف المدرسة والطالب.
- لا يستطيع ولي الأمر إرسال طلب لربط طالب بمدرسة لا يختارها، ولا تظهر له بيانات طالب آخر دون رابط معتمد.

### تفعيل متابعة ولي الأمر
1. افتح `/guardian` وأنشئ حساب ولي أمر أو سجّل الدخول بحسابك الحالي.
2. اختر المدرسة، وأدخل البريد الذي يستخدمه الطالب في حسابه المدرسي، ثم أرسل الطلب.
3. على مدير المدرسة فتح قسم «أولياء الأمور» في `/school-admin` ومراجعة الطلب. لا يمكن اعتماد الطلب إلا إذا كان البريد مطابقًا لحساب طالب معتمد ونشط في تلك المدرسة.
4. بعد الاعتماد، حدّث صفحة متابعة الأبناء لعرض الواجبات والنتائج المتاحة.

### حدود الإصدار 2.21.0

ملاحظات: سجل التدقيق وملفات المعلمين والجلسات تخزين محلي على الخادم ويحتاج `DATA_DIR` إلى Volume دائم على Railway. هذا ليس تدقيقًا أمنيًا مستقلًا، ولا يتضمن بعد استعادة الحساب أو التحقق من البريد أو نظام صلاحيات متعدد المستويات. لا تستخدمه للإنتاج العام قبل مراجعة أمنية واختبار إعدادات النشر.

## إعداد دخول المدير
1. انسخ متغيرات `.env.example` إلى إعدادات بيئة التشغيل، ولا ترفع ملف الأسرار إلى GitHub.
2. اضبط `ADMIN_EMAIL` و`ADMIN_PASSWORD` بقيم خاصة وفريدة وقوية.
3. على Railway، أضف المتغيرات من إعدادات الخدمة واضبط `DATA_DIR` على مسار Volume دائم.
4. افتح قسم «دخول إدارة المنصة» وسجّل الدخول لفتح أدوات المناهج والمحتوى.

## حدود أمنية مهمة — لا تعتبره جاهزًا للإنتاج
هذا تنفيذ أولي للتجربة وليس نظام حسابات إنتاجيًا. لا توجد حتى الآن آلية لاستعادة كلمة المرور أو التحقق من البريد أو إدارة الجلسات من الحساب. نظام الأدوار في هذا الإصدار يفصل مدير المنصة عن ولي الأمر، لكنه لا يوفّر بعد حسابات مستقلة للمعلّمين بصلاحيات محدودة أو سجل تدقيق شامل. تحديد المعدل محلي للعملية ويعتمد على عنوان اتصال الخادم، ويحتاج إلى طبقة إضافية عند استخدام عدة نسخ خلف وكيل عكسي. حماية الإدارة في هذا الإصدار خطوة أولية وليست تدقيقًا أمنيًا شاملًا؛ كلمة مرور المدير تأتي من متغير بيئة، وجلسات الإدارة محفوظة في ملف JSON محلي. لا توجد بعد استعادة حساب أو تحقق بريد أو صلاحيات منفصلة للمعلم أو سجل تدقيق شامل. لا تفتح النسخة للعامة أو ترفع مناهج حساسة قبل إضافة تسجيل دخول وصلاحيات إدارية مستقلة ومراجعة أمنية. يلزم HTTPS دائمًا، ومراجعة حماية البيانات وموافقة ولي الأمر قبل استخدامه مع أطفال حقيقيين.

## متطلبات تشغيل PDF — إلزامية

معالجة ملفات PDF جزء أساسي من المنصة وليست ميزة اختيارية. قبل تشغيل الخادم على جهاز جديد أو Railway، يجب تثبيت اعتماديات الإنتاج باستخدام `npm ci` عند وجود `package-lock.json`، أو `npm install` إذا لم يوجد ملف قفل. إذا كانت مكتبة `pdf-parse` غير متاحة، يتوقف الخادم عند بدء التشغيل بدل تشغيل منصة تعليمية معطّلة جزئيًا.

تنبيه وظيفي: استخراج النص الحالي يدعم ملفات PDF النصية. ملفات الكتب المصوّرة التي لا تحتوي طبقة نص تحتاج OCR. كما أن مسار تسليم الواجبات الحالي ما زال يعتمد الإجابة النصية؛ لا تعتبر رفع ملفات واجبات PDF ومعاينتها وتصحيحها مدعومًا حتى يُنفّذ ويُختبر مسار المرفقات الخاص بها.

## Version 2.30.0 — public curriculum downloads
- Added a public read-only curriculum catalog on the homepage. Visitors can search by book title, grade, subject, and available term metadata, and download PDF files without an account.
- Added `GET /api/public/curriculum/pdf/:id`; it only serves catalog books marked as PDF uploads, uses server-stored filenames, and returns an attachment response.
- Upload and curriculum processing remain admin-only. Public catalog visibility does not expose extracted book text.
- Downloading requires the original PDF to exist in the configured persistent data directory; configure a persistent Railway volume for `DATA_DIR`.


### Large PDF book uploads

The curriculum PDF upload limit defaults to `MAX_PDF_UPLOAD_MB=300` (megabytes). Set this environment variable in Railway to a value between 1 and 1024 if needed. Large PDFs require sufficient service memory, disk space, and upload time; platform/proxy limits may still apply. For files that fail at the hosting edge, resumable/chunked uploads and object storage are the robust next step.
